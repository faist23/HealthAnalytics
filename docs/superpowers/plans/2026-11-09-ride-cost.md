# Ride Cost Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Price every ride by what its intensity should cost Craig (heart rate and feel against his own same-setting rides at that intensity), flag costly rides on the Coach tab, ease the plan from the trend, and remove Forecast Check.

**Architecture:** A pure `RideCost` enum replaces `EffortAbsorption` and works on `PricedRide` values built in `ReadinessRepository` from `StoredWorkout` plus real FTP snapshots. A new optional `StoredWorkout.isIndoor` comes from Strava (decoded on every sync, plus a one-time 120-day fill). The plan's feel shift is fed by `RideCost.trend`; a published `rideCostFlag` drives a Coach card.

**Tech Stack:** Swift, SwiftUI, SwiftData, XCTest.

**Spec:** `docs/superpowers/specs/2026-11-09-ride-cost-design.md`

## Global Constraints

- Numbers: rides ≥ 20 min; comparable = before the ride, ≤ 90 days, same setting, intensity ±0.05, duration ±30%, ≥ 3 rides; HR dead band 4 bpm; feel dead band 1 point; 4 bpm = 1 point; flag at HR cost ≥ 8 bpm or feel cost ≥ 2; card for rides in the last 3 days (today included); trend over 14 complete days, half-life 4 days, priorWeight 1.0, −0.5 spread per point, clamp ±1.
- A negative part is dropped when the other part is positive (low HR never cancels a hard feel; a ride is cheaper only when neither part is positive).
- Real FTP only: the newest `StoredFTPSnapshot` dated ≤ ride start; never the 200 W fallback.
- Indoor when Strava type or sport_type is `VirtualRide`, or `trainer` is true, or `map.summary_polyline` is empty/missing; otherwise outdoor.
- Reason line copy: "Rides costing more than usual" / "Rides costing less than usual".
- Card wording describes, never guesses a cause. Colors and fonts from DESIGN.md tokens (`Color.surface`, `Color.textPrimary`, `Color.textSecondary`, `Color.accent`), explicit `Color.x` form.
- Test lane: `xcodebuild test -project HealthAnalytics.xcodeproj -scheme HealthAnalytics -destination 'platform=iOS Simulator,name=iPhone 17 Pro,OS=26.5' -only-testing:HealthAnalyticsTests`

## Review Focus

1. A HealthKit-only refresh or Watch match re-upserting a Strava ride must not clear its `isIndoor` (upsert writes it only when non-nil): `testUpsert_nilIndoorKeepsStoredValue`.
2. A ride whose own date has no FTP snapshot but a later one exists is unpriced (`noFTP`), not priced at the later FTP: `testPricing_snapshotAfterRideIsNoFTP`.
3. Today's flagged ride shows the card immediately but does not move the trend until tomorrow: `testFlag_todaysRideFlags` + `testTrend_skipsToday`.
4. The one-time fill marks itself done only when every page it needed came back: `testIndoorFill_stopsAtCutoff` (pure page decision) and `applyIndoorFlags` only setting rows that are nil or differ.
5. A ride compared only against rides after it (backdated upload) is not judged by them: `testPrice_ignoresLaterRides`.

### Task 3: RideCost pricing (pure)

**Files:**
- Create: `HealthAnalytics/Services/Analytics/RideCost.swift` (replaces `EffortAbsorption.swift`, which is deleted along with `EffortAbsorptionTests.swift`)
- Test: `HealthAnalyticsTests/RideCostTests.swift`

**Interfaces (produces):**
```swift
struct PricedRide: Equatable { let id: String; let date: Date; let title: String?; let minutes: Double
    let intensity: Double; let heartRate: Double; let rating: Double?; let isIndoor: Bool }
struct RidePrice: Equatable { let heartRateCost: Double?; let normalHeartRate: Double?
    let feelCost: Double?; let normalRating: Double?; let cost: Double? }   // cost nil when neither part judged
enum UnpricedReason: String, CaseIterable { case tooShort, noPower, noHeartRate, noFTP, unknownSetting }
enum RidePricing: Equatable { case priced(PricedRide), unpriced(UnpricedReason) }
struct RideCostFlag: Equatable { let date: Date; let title: String?; let heartRateAbove: Int?
    let rating: Int?; let normalRating: Int?; var eased: Bool = false
    var lines: [String] }      // copy, see below
enum RideCost {
    static func realFTP(for date: Date, snapshots: [StoredFTPSnapshot]) -> Double?
    static func pricing(id:date:title:minutes:isCycling:normalizedPower:averagePower:heartRate:rating:isIndoor:ftp:) -> RidePricing?   // nil for non-cycling
    static func price(_ ride: PricedRide, among rides: [PricedRide]) -> RidePrice
    static func trend(_ rides: [PricedRide], now: Date, calendar: Calendar) -> Double
    static func zShift(trend: Double) -> Double
    static func flag(_ rides: [PricedRide], now: Date, calendar: Calendar) -> RideCostFlag?
}
```
Constants per Global Constraints. `pricing` checks in order: minutes < 20 → tooShort; no NP and no avg power (> 0) → noPower; no HR (> 0) → noHeartRate; ftp nil → noFTP; isIndoor nil → unknownSetting. Intensity = (NP ?? avg) / ftp. Medians as in the old `EffortAbsorption.expectedRating`. `price`: comparable = other rides, same `isIndoor`, `date < ride.date`, `ride.date − other.date ≤ 90 days`, intensity and duration within tolerance. HR part needs 3 comparable; feel part needs 3 comparable with a rating and the ride rated. Dead bands map to 0. Points: HR cost / 4. Drop a negative part when the other is positive. `trend`: as `EffortAbsorption.trend` over `price(...).cost`. `flag`: newest ride with day age 0...2 whose HR cost ≥ 8 or feel cost ≥ 2.

Copy (`RideCostFlag.lines`), rating words 1–3 easy, 4–6 moderate, 7–8 hard, 9–10 all out:
- "Heart rate \(n) bpm above your normal for this effort" when `heartRateAbove` ≥ 8
- "Felt \(word(r)) (\(r)) where rides like it feel \(word(u)) (\(u))" when the feel flagged
- "The coming days are eased." when `eased`
