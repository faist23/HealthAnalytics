# Design: Dynamic Master Coach Engine

## Problem Statement
The app provides fragmented and sometimes conflicting coaching advice. It lacks a unified voice that synthesizes current readiness, intraday fatigue (post-workout updates), and the 7-day forecast. Users need a reliable, adaptable "Master Coach" paragraph that updates dynamically throughout the day.

## What Makes This Cool
A true "Coach" voice that understands the delta between how you woke up and how you feel now. If you woke up at 85% but did a hard morning ride, the coach acknowledges both states: "You woke up primed, and you used it well. Your current readiness is 42%, so take it easy the rest of the day. Based on your 7-day forecast, you're on track for a rest day tomorrow."

## Constraints
- Must update immediately after workouts (intra-day decay).
- Must preserve the big visual scores.
- Must reconcile conflicting component signals using the GEMINI.md Reconciler Rule.

## Premises
1. The big hero scores stay, but the text beneath them becomes a dynamic 'Master Coach Summary'.
2. This summary instantly rewrites itself after a morning workout to reflect the newly fatigued state.
3. It must synthesize real-time fatigue + the 7-day forecast.

## Approaches Considered
### Approach A: Rule-Based Extension
Extend the existing `CoachingService` to accept the 7-Day Forecast and Intra-Day Strain as new inputs.
### Approach B: Master Coach Template Engine
Deprecate the fragmented fields (headline, subline, targetAction) and build a `MasterCoachEngine`. It evaluates a state vector (current readiness, intraday fatigue, forecast, active DNA patterns) and generates a single, human-like paragraph.
### Approach C: Intraday Overlay Component
Keep the "Morning Plan" static, but overlay a "Current Status" block that appears ONLY after a workout, projecting tomorrow's recovery needs.

## Recommended Approach
**Hybrid Master Coach Engine (B + C)**: Build a heuristic engine (Approach B) that generates a unified paragraph, but explicitly include the morning-to-current delta (Approach C's value) in the state vector. The engine will explicitly reference both the beginning-of-day state and current state if a workout has occurred, ensuring the user understands exactly *why* the advice changed.

## Open Questions
- What is the precise threshold of intra-day strain required to trigger a change in the coaching text?
- How do we handle multiple workouts in one day?

## Success Criteria
- The coaching text never contradicts the active DNA patterns, readiness score, or 7-day forecast.
- A morning workout measurably alters the coaching text upon returning to the app.
